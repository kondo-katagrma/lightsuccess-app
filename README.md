# マネジメントスケジュール診断（チーム共有版）

診断ツールをアプリ化し、**法人ごとの診断結果をチームの共有台帳に蓄積・閲覧・比較**できるようにしたものです。

- **アプリ本体（CS用）**：`index.html`（GitHub Pages で全員に配布。プラン作成・レベル判定・蓄積一覧など全機能）
- **アプリ本体（顧客回答用）**：`respond.html`（法人ごとに発行するURLで、アンケート部分だけに答えてもらう。プラン・レベル判定は表示しない）
- **アプリ本体（プラン共有用）**：`plan.html`（CSがプランを完成させた後、その法人にだけ結果を見せるための閲覧専用ページ。編集不可・他法人のデータは見えない）
- **共有データ**：Google スプレッドシート（全員が閲覧・集計できる台帳）
- **中継**：`apps-script/Code.gs`（アプリ ⇄ スプレッドシート をつなぐ小さなプログラム。CS用のフル操作トークン、顧客回答用の「新規追加のみ」トークン、プラン共有用の「id指定で1件だけ閲覧」トークンの3つを分けている）

```
[CSのブラウザ]        ──診断・保存・一覧閲覧──▶ [Apps Script] ──追記/更新──▶ [共有スプレッドシート]
                                                    ▲            │
[法人担当者のブラウザ] ──アンケート回答の送信のみ──┘            │
      （respond.html は新規追加しかできない）                    │
[法人担当者のブラウザ] ──idを指定してプラン1件だけ閲覧──────────┘
      （plan.html は一覧取得不可、共有されたidのプランしか読めない）
```

`index.html` の「診断する」画面から、法人ごとの回答URL（`respond.html?hojin=…&visit=…`）を発行してコピーできます。法人が回答すると「サイクル・開始月・プラン未設定」のレコードとして台帳に貯まるので、CSは「蓄積一覧・比較」タブの **「続きを入力する →」** から続きを行い、プランを完成させます。プランが完成したら、「プラン・メモを表示」モーダルの **「🔗 このプランを法人と共有するURLを発行」** から `plan.html?id=…` のリンクを発行し、対象法人にだけ結果を共有できます。

## セットアップ（初回だけ・近藤さんが実施）

### 手順1：共有スプレッドシートを作る
1. Google ドライブで新しいスプレッドシートを作成（名前は「診断台帳」など任意）。
2. チームメンバーに**閲覧（または編集）権限**で共有しておく。
3. **法人名リスト（開始時に選ぶ一覧）**について。
   - アプリは **`records` シート以外の「最初のシート」のA列** を法人名の一覧として読み込みます。
   - 既存の取引先マスタ（A列＝取引先名）をそのまま使えます。見出し行（`取引先名`／`法人名`）や空セルは自動で除外されます。
   - 別のシート・別の列を使いたい場合は `Code.gs` の `MASTER_SHEET`（シート名）と `MASTER_COL`（列番号）を設定。
   - ※ 一覧に無い法人は、開始画面で**そのまま手入力**もできます。

### 手順2：Apps Script を貼り付ける
1. そのスプレッドシートで **拡張機能 → Apps Script** を開く。
2. 既定の `コード.gs` の中身を全部消し、`apps-script/Code.gs` の内容を丸ごと貼り付ける。
3. `TOKEN`（CS用・全操作）、`SUBMIT_TOKEN`（顧客回答用・新規追加のみ）、`VIEW_TOKEN`（プラン共有用・id指定で1件だけ閲覧）は、それぞれ `index.html` / `respond.html` / `plan.html` と一致する値が設定済みなので**そのまま**でよい（変えるなら該当する2ファイルとも同じ値に）。
4. 保存する（フロッピーアイコン）。

> **Code.gs を更新したら必ず再デプロイ**：Apps Script は貼り付け・保存だけでは公開版に反映されません。
> 右上 **デプロイ → デプロイを管理 → （鉛筆で編集）→ バージョン＝新バージョン → デプロイ** を行うこと。URLは変わりません。

### 手順3：ウェブアプリとしてデプロイ
1. 右上 **デプロイ → 新しいデプロイ**。
2. 歯車（種類の選択）→ **ウェブアプリ** を選ぶ。
3. 設定：
   - 説明：任意
   - **次のユーザーとして実行**：自分（近藤さん）
   - **アクセスできるユーザー**：**全員（匿名アクセスも含む）**
     （法人担当者は katagrma.co.jp のGoogleアカウントを持っていないため、`respond.html` からの回答を受け付けるにはこの設定が必須。「KatagrMa内の全員」のままだと顧客は回答できません。公開されるのはこのApps ScriptのURLだけで、スプレッドシート自体の共有設定は別なので、台帳を直接見られるわけではありません。）
4. **デプロイ** を押し、表示される **ウェブアプリのURL**（`https://script.google.com/macros/s/……/exec`）をコピー。
   - 初回は Google の承認画面が出るので許可する。

> **⚠️ セキュリティ上の注意**：デプロイを「全員」にすると、理論上は誰でもこのURLを直接叩けます。それでも他法人のデータが読めないのは、`list`（一覧閲覧）や `update`（更新）が **CS用の `TOKEN`** を要求し、`respond.html` にはこの `TOKEN` を一切埋め込んでいないためです（`respond.html` が知っているのは新規追加専用の `SUBMIT_TOKEN` だけ）。**`index.html` に埋め込まれている `TOKEN` の値自体は、ページのソースを見れば誰でも読み取れる**という前提を忘れないでください（漏れても実害が小さいよう新規追加のみ許可する設計です）。本気で守りたい情報を台帳に書かない、という運用面での注意も引き続き必要です。

### 手順4：アプリにURLとトークンを設定
`index.html` の先頭付近、`CONFIG` を編集：

```js
const CONFIG={
  API_URL:"https://script.google.com/macros/s/……/exec",  // ← 手順3のURL
  TOKEN:"kata-2026-xxxx"                                    // ← 手順2で決めた TOKEN と同じ
};
```

`respond.html` の先頭付近、`CONFIG` も同じURLで設定（**TOKENは書かない**）：

```js
const CONFIG={
  API_URL:"https://script.google.com/macros/s/……/exec",  // ← 手順3のURL（index.htmlと同じ）
  SUBMIT_TOKEN:"kata-ls-submit-xxxx"                       // ← Code.gs の SUBMIT_TOKEN と同じ
};
```

`plan.html` の先頭付近も同様（**TOKEN・SUBMIT_TOKENは書かない**）：

```js
const CONFIG={
  API_URL:"https://script.google.com/macros/s/……/exec",  // ← 手順3のURL（同じ）
  VIEW_TOKEN:"kata-ls-view-xxxx"                           // ← Code.gs の VIEW_TOKEN と同じ
};
```

### 手順5：GitHub Pages で公開
1. このフォルダを GitHub リポジトリにする：
   ```bash
   cd lightsuccess-app
   git init
   git add .
   git commit -m "診断アプリ（チーム共有版）初版"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```
2. GitHub のリポジトリ **Settings → Pages** で、Source を **main / (root)** にして保存。
3. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される。
   このURLをメンバーに配れば、全員が同じアプリを使い、結果が共有台帳に貯まります。

## 使い方（CSメンバー・自分で診断する場合）

1. `index.html` の配布URLを開く。
2. 最初に **法人を選択**（登録済みマスタから選ぶ／手入力）して診断を開始。
3. **「診断する」** で設問に回答 → 年間プラン／半年のライトサクセスが表示される。
4. 打合せ中は、結果画面の **打合せメモ欄** にその場で記入 → **「この結果を保存」**。
   - 一度保存するとボタンが **「メモを更新して保存」** に変わり、同じ画面で追記しても**同じ行を上書き**します（重複行はできません）。
5. **「蓄積一覧・比較」** タブで、全法人の保存結果・メモ・観点の傾向・開始月の分布を確認。
   - 各行の **「プラン・メモを表示」** でプランとメモを再表示。**メモはここで後から追記・修正でき**、「メモを保存（この行を上書き）」でその行を更新できます。
6. プラン内の **テンプレ名（▸付き）** をクリックすると、面談テンプレの設問や自己評価テンプレの一覧が表示されます。

## 使い方（法人に直接回答してもらう場合）

1. `index.html` の開始画面で、法人名と「診断の種類（初回／2回目以降）」を選ぶ。
2. **「この法人の回答URLを発行してコピー」** を押す（クリップボードに `respond.html?hojin=…&visit=…` の形式のURLがコピーされる）。
3. そのURLをメール・LINEなどで法人担当者に送る。担当者はアンケート（＋今年度重視したいテーマ）に答えて送信するだけで、プランやレベル判定は表示されない。
4. 送信されると、共有台帳に「サイクル・開始月・プラン未設定」のレコードが1件追加される。
5. CSは「蓄積一覧・比較」タブを開くと、そのレコードの開始月列に **「要プラン作成」** タグが付いているので、**「続きを入力する →」** を押す。
6. 回答内容を引き継いだまま「振り返りのサイクル」「契約開始月」の続きから入力すると、通常通りプランが完成し保存できる（同じレコードが上書きされ、重複行にはならない）。
   - 継続利用の法人（診断の種類＝2回目以降）は、契約開始月のデフォルトが**4月**になります（次年度に向けた計画のため）。必要なら変更可能です。
7. プランが完成したら、「プラン・メモを表示」モーダル下部の **「🔗 このプランを法人と共有するURLを発行」** で `plan.html?id=…` のURLを発行し、対象法人にだけ送る。法人はそのリンクで自分たちのプランだけを閲覧できる（編集不可、他法人のデータは見えない、打合せメモは非表示）。

## よくある調整

- **TOKEN を変えたい**：`Code.gs` と `index.html` の両方を同じ値にして、Apps Script を**再デプロイ**（デプロイ → デプロイを管理 → 編集 → 新バージョン）。
- **項目を増やしたい**（事業所コード・地域など）：`Code.gs` の `getSheet()` のヘッダーと `handleSave` の `appendRow`、`index.html` の保存フォームに列を足す。
- **スプレッドシートで直接集計したい**：台帳シートはそのままピボット・フィルタで使えます（payload列は再表示用のデータなので触らないこと）。
- **テンプレの中身を直したい**：プラン内のテンプレ名（▸付き）をクリックすると内容が表示されます。面談テンプレの設問は `index.html` の `TEMPLATES` に埋め込み済みです。元の面談テンプレ／自己評価テンプレのスプレッドシートを更新したら、`TEMPLATES` も合わせて手直ししてください（自己評価はリンク表示なので基本そのままでOK）。

## 注意（アクセス範囲について）
- Apps Scriptのデプロイは **「全員（匿名アクセスも含む）」** です（`respond.html` から法人担当者が回答できるようにするため）。`index.html`（CS用）を使う際は、特にログインは必要ありません。
- CS用の `list`（一覧閲覧）・`update`（更新）・`save`（新規保存）は `TOKEN` を要求し、`respond.html`/`plan.html` はこれを一切知らないため、顧客用URLが漏れても他法人のデータ閲覧・改ざんはできません（`respond.html`でできるのは新規のアンケート回答を1件追加することだけ、`plan.html`でできるのはURLで指定された1件のプランを閲覧することだけで、一覧取得はできません）。ただし `index.html` に埋め込まれた `TOKEN` の値自体はページソースから読み取れる、という前提は忘れないでください（詳しくは手順3参照）。
- `plan.html` で法人に見せる内容には、CSの打合せメモ（内部メモ）・記入者名は含まれません（Code.gsの `handleGetPlan` で意図的に除外）。
- 台帳には法人名・担当者名が入ります。個人が特定される回答自由記述などは基本保存していません（診断は選択式が中心で、自由記述欄も業務課題・期待に関するものに限定）。
- 動かないとき：①`Code.gs` を直した後に**再デプロイ（新バージョン）**していない → 反映されない（`?action=ping`で`version`を確認すると分かりやすい）。②`index.html`/`respond.html`/`plan.html`/`Code.gs` のトークンが食い違っている → 認証エラーになる。③スプレッドシートが個人アカウント側にあり「全員」の選択肢が出ない → 組織ドライブ上で作り直す。
